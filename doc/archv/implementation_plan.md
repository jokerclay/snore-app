# 极简打鼾监控 App (Snore App) 思考与实施方案

## 一、核心思考与痛点拆解

要做到 **“App 简洁（开发结果）+ 开发环境简洁（开发过程）”**，必须直击打鼾监控这件事的核心本质与最大坑点：

### 1. 为什么市面上的打鼾 App 很难用？
- **臃肿与广告**：充满社交、床垫商城、订阅制付费、复杂的睡眠评分算法。
- **存储杀手**：如果整夜持续录音，8 小时会产生几百兆甚至几 GB 文件，手机存储很快告急。
- **后台被杀**：Android 现代版本（Android 12/13/14/15）对“后台录音”管控极严，锁屏半小时往往就被系统杀进程或麦克风静音。
- **耗电发热**：整晚持续跑大模型或复杂图像/音频运算，醒来手机发烫、电池掉 30% 以上。

### 2. 我们的极简破局解法
1. **音频只留精华（环形缓冲区）**：
   - 内存维护 5 秒的环形音频缓冲（Circular Buffer）。
   - 平时只分析特征，不落盘；一旦判定为打鼾事件，才把当前及前后数秒导出为 `.m4a` / `.wav` 小音频切片。
   - 一整夜下来可能只产生十几个 100KB 的小片段，总占用 < 2MB。
2. **后台绝不掉线**：
   - 标准 Android `FOREGROUND_SERVICE_MICROPHONE` + `PARTIAL_WAKE_LOCK`。
   - 界面提供一键打开“忽略电池优化”，保证安心睡一整夜。
3. **黑夜防刺眼 (AMOLED-friendly)**：
   - 夜间录音界面支持纯黑省电模式（近乎关闭像素），低功耗且不影响睡眠。

## 二、开发环境极简设计

| 维度 | 传统重型方案 | 我们的极简推荐方案 |
| :--- | :--- | :--- |
| **技术栈** | Flutter / React Native / Python 后端 | **纯原生 Kotlin + Jetpack Compose** |
| **环境依赖** | 需要配 Node, CocoaPods/Flutter SDK, NDK C++ 交叉编译 | **只需 Android Studio 开箱即用**（内置 JDK，零额外配置） |
| **算法实现** | 引入庞大的 Python 转换模型 / C++ DSP 库 | **纯 Kotlin 编写轻量音频特征计算**（RMS 能量自适应 + 频域带通） |
| **打包产物** | 动辄 40MB ~ 80MB | **单 APK < 10MB**，冷启动 < 0.5s |

## 三、打鼾检测算法方案演进

### 第一阶段（纯数学声学算法，耗电几乎为零）
打鼾声音有极其鲜明的生物声学特征：
1. **低频共鸣**：鼾声能量集中在 **150Hz ~ 800Hz**，普通翻身摩擦是宽频白噪，高频尖锐声 > 2000Hz。
2. **持续时间**：单次吸气鼾声通常在 **0.6 秒 ~ 2.5 秒** 之间，不会是几毫秒的敲击声，也不会是持续数分钟的长鸣声。
3. **周期性**：伴随呼吸节奏，通常间隔 2 ~ 5 秒出现一次。
4. **自适应底噪**：动态追踪夜间环境底噪（如 32dB），当瞬时能量 > (底噪 + 12dB) 且满足低频时长时，判定为疑似打鼾。

### 第二阶段（本地 AI 离线模型，按需开启）
- Google 官方开源预训练好的 **YAMNet (TFLite，约 3.7MB)**。
- 只有第一阶段粗筛命中后，才唤醒该模型推理 0.975 秒切片进行类别校验（类别包含 `Snoring`），兼具准确率与极低功耗。

## 四、极简页面规划（共 2 屏）

1. **主屏幕 (Night Mode & Controller)**
   - 一个醒目的大按钮：`开始监测` / `醒来停止`。
   - 实时分贝微弱动效。
   - 夜间全黑遮罩模式，防止屏幕刺眼。
2. **记录报告页 (History & Timeline)**
   - 统计卡片：昨夜打鼾总次数、累计打鼾时长、最高分贝。
   - 时间轴分布图：清晰看到几点几分打呼噜最频繁。
   - 录音回听列表：每一段打鼾支持一键试听与手动删除。

---

## 五、下一步落地步骤

1. **环境准备**：确认 Android Studio 或 Gradle 命令行环境。
2. **骨架搭建**：创建纯净的 Android Compose 项目结构。
3. **音频流水线**：编写轻量 `AudioRecordEngine`（PCM 采样 + 环形缓冲 + 分贝计算）。
4. **后台常驻服务**：封装 `SnoreMonitorService` 与前台通知，确保过夜稳定。
5. **回听与存储**：接入 Room 本地数据库，保存打鼾时间戳与音频切片。
