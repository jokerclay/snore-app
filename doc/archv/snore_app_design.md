# 极简打鼾监控 App (Snore Monitor) 架构与技术方案

## 1. 核心设计理念

- **自用优先 (Personal-first)**：零广告、零社交、零云端上传，数据 100% 存储于本地。
- **开发环境极简 (Minimal Dev Environment)**：不依赖复杂的第三方平台或交叉编译环境，单靠标准 Android Studio + Kotlin 即可完整开发与调试。
- **结果形态极简 (Minimal End Product)**：
  - 核心功能聚焦：后台录音 -> 打鼾检测 -> 记录片段 -> 晨起生成图表回听。
  - 极小安装包（< 15MB），极低功耗与 CPU 占用，适合整晚运行。

---

## 2. 技术选型权衡 (开发环境极简视角)

| 方案 | 优点 | 缺点 | 结论 |
| :--- | :--- | :--- | :--- |
| **Flutter / React Native** | 跨平台，写 UI 快 | 后台保活机制复杂；录音和底层音频流处理需要封装原生插件，环境笨重 | ❌ 不推荐 |
| **Android 原生 (Kotlin + Jetpack Compose)** | 官方标准工具链；后台服务 (Foreground Service) 与低电耗录音控制最直接稳定；无需额外跨平台依赖 | 仅限 Android (但能做到极致省电与不被杀进程) |  **最佳推荐** |

## 3. 打鼾检测核心策略 (两步走演进)

### 阶段一：纯数学/声学特征过滤 (零依赖、毫秒级响应、超省电)
整晚录音如果全量保存，文件可达数百 MB 且极耗电。因此采用**“轻量检测 + 静音/无关噪音丢弃”**：
1. **音频采集**：16kHz / 单声道 PCM（降低计算量与内存）。
2. **响度自适应底噪 (RMS / dB)**：
   - 动态计算环境底噪基准值。
   - 当声音能量超过底噪一定阈值（如 +12dB）时触发判定窗口。
3. **打鼾声学特征筛选**：
   - **频率聚集**：打鼾多集中在 **150Hz ~ 1000Hz**（相比说话、翻身、高频尖锐声有显著低频特征）。
   - **时间/持续时长**：每次鼾声吸气通常在 **0.5秒 ~ 3.0秒** 之间，具有呼吸周期的节奏性。
4. **切片保存**：只把疑似打鼾的前后 5 秒保存为音频文件供回听，其余静音段直接丢弃。

### 阶段二：离线 AI 分类器 (若需极致准确率)
- 基于 Google 官方开源的 **TFLite + YAMNet (音频分类模型)**。
- 模型不到 4MB，直接在本地对声音片段进行推断（输出类别包含 `Snoring`），不发请求不上云。

## 5. 整夜后台防杀与电池优化核心清单

在 Android 上做整夜睡眠类 App，最关键的问题是**防止系统在凌晨低电量或深度休眠时杀掉录音进程**：
- **前台服务 (Foreground Service)**：绑定带有常驻通知的服务（`FOREGROUND_SERVICE_MICROPHONE`）。
- **WakeLock**：申请 `PARTIAL_WAKE_LOCK` 保证 CPU 维持低频运行处理音频缓冲。
- **电池优化白名单**：引导用户在系统设置中为本 App 开启「无限制 / 允许后台高耗电」。
